- How do we evaluate our classifiers? How do we compare between classifiers?
- Ways to evaluate classifiers:
	- Predictive accuracy:
		- $accuracy = \frac{\text{number of correct classifications}}{\text{total number of test cases}}$
		- Can also use **error rate**
			- error rate - 1 - accuracy
		- **Accuracy is not suitable in many applications**
			- Ex: test mining - we might only be interesting in documents of a particular topic
			- Ex: In highly skewed data - we might only be interested in a minority class
				- We achieve high accuracy by doing nothing for 1% intrusion rate
	- Efficiency:
		- Time to construct the model, time to use the model
	- Robustness:
		- How well does it handle noise or missing values?
	- Scalability:
		- How efficient is the algorithm w/ large data? What about power usage?
	- Interpretability:
		- Understandable and insight provided by the model
		- __Decision trees have a very good interpretability!
	- Compactness:
		- Size of the model: size of tree or number of rules
		  
	- Of course, the importance of all of these depends on our application!
		- Ex: in some cases we need to know why a classification occurs not just a yes or no
# 3.3.1 - Evaluation methods

- **[[Holdout Set]]** (also called the test set)
	- __A subset of data that is withheld from training to evaluate a model's performance on unseen data__
	- Aka we split our data into training and test sets.
		- We should avoid using the test set for training and the training set for testing.
			- This is not always done in practice...
	- Formally, data $D$ divided into 2 disjoint subsets
		- Training set $D_{train}$ (for learning)
		- Test set $D_{test}$ (for testing)
		- D<sub>train</sub> $\cup$ D<sub>test</sub> = $D$
		- D<sub>train</sub> $\cap$ D<sub>test</sub> = $\emptyset$ 
	- Used when D is **large**, assumes D is labeled with classes
	- Avoid using training set in the evaluation due to avoid [[overfit]]ting
	- Common ratios of data testing are 1/2 and 2/3 training to test data.
	- 2 approaches to building holdout sets:
		- Randomly sample from D for learning and use the remaining data for testing
		- Or if data is collected over a period of time to use the early data for learning and later data for testing
	- **[[Multiple Random Sampling]]**
		- Small data set can lead to Holdout set being unreliable
		- Small data set -> too small to be representative
		- So we perform random sampling *n* number of times to produce *n* training sets and *n* test sets
		- Average *n* accuracies together for final estimated accuracy
	  
- [[Cross validation]]
	- used with small data sets
	- [[n-fold cross-validation]]
		- partition data into *n* equal-size disjoint subsets
		- For a set of $n$ equal-sized, disjoint subsets: train the model on $n-1$ of the subsets, then validate on the remaining subset.
		- Procedure is ran $n$ times for $n$ accuracies and averaged
		- Common n sizes are 10 and 5
		- Ex: say we have 100 data points
			- we can split data into 5 bins, use 4 bins for training and 1 for testing.
			- Then we can run the test 5 times because we have 5 different equal sized bins
		- ![[Pasted image 20260228174053.png]]
		- **Good for small datasets** 
			- Deep learning does not do well on small data.
		- Not used too often because we don't usually have a sparse amount of data
	- [[leave-one-out cross-validation]]
		- **Used in the extreme small data set size**
		- Each fold of cross validation uses 1 test example
		- Rest of data in the fold is used for training
		- Inefficient for large data sets
		- If test data has *m* examples this is called m-fold cross-validation
	- [[3.2 - Decision Tree Induction]] discussed [[validation set]]s for prune decision trees or sets of rules
		- Sometimes we split the data into 3 subsets instead of 2
			- Training
			- validation
			- test
		- **Validation set** - For estimating parameters in learning algorithms
			- Parameters that give the best accuracy on the validation set are used as the final parameter values
			- Hyperparameter tuning and model selection, used during model training
		- Sometimes people use the test set as the validation set
			- this *used* to be a problem - but since we have so much data it doesn't really matter anymore
		- We can also use cross-validation for parameter estimation too.
		- Validation sets should not be used in testing in this case
		- data is partitioned into training, validation, and test sets 
		- Can be used to estimate params in learning algorithms
# 3.3.2 - Precision, Recall, F-score, Breakeven Points
- Some applications are only interested in one class or a minority class
	- In this case accuracy is not very useful, (ex: sometimes we can achieve 99% accuracy by doing nothing depending on the skew of the data)
- [[positive class]] - the class that the user is interested in
- [[negative class]] - a class that the user is not interested in
- We can't use accuracy for these cases 
	- Ex: network intrusions and fraud detection - 99% of cases are normal in an intrusion data set -> classifiers achieve high accuracy without doing anything (classing every test case as "not intrusion" is useless)
- So we use precision and recall (from information retrieval and text classification)
- [[confusion matrix]] - Contains information about actual and predicted results given a classifier
	- Actual positive vs classified positive -> true positive (TP)
	- Actual positive vs classified negative -> false negative (FN)
	- Actual negative vs classified positive -> false positive (FP)
	- actual negative vs classified negative -> true negative (TN)
- [[precision]] (p) - How precise a classification is on a positive class
	- Precision of positive class: $p = \frac{TP}{TP + FP}$ 
	- Number of correctly classified positive examples over total positive examples classified as positive
- [[recall]] (r) - How complete a classification is
	- Recall of a positive class: $r = \frac{TP}{TP + FN}$ 
	- Number of correctly classified positive examples over the total positive examples in the test set
- **Precision and recall only measure classification on a positive class.**
- **Theoretically - precision and recall are not related. But practically, they are!**
- Ex of an application where precision doesn't matter:
	- Search engines - we really only care about the first few results we get! Number of false positives doesn't really matter
- Not easy to compare classifiers based on 2 measures that aren't related, we can have high precision but low recall, for example
- Often times one is achieved at the detriment of the other (PARETO OPTIMIALITY???)
- [[F-score]] often used to compare classifiers instead
	- Sometimes we produce precision, recall, and F-score
	- $F_1$ score combines precision and recall into 1 measure
	- $F = \frac{2pr}{p + r}$
	- Harmonic mean of [[precision]] and [[recall]]: $F_1 = \frac{2}{\frac{1}{p} + \frac{1}{r}}$
		- Harmonic of 2 numbers is closer to the smaller of the two numbers, so high F-score means high precision and recall
- precision and recall [[breakeven point]] - when precision and recall are equal
	- assumes test cases can be ranked by the classifier based on chance of being positive

# 3.3.3 Receiver Operating Characteristic (ROC) Curve
- What happens if we can't do a precise application?
	- It's very difficult to classify a very small positive rate (eg 1%)
	- In decision trees we can get a probability by looking at leaf nodes and create a ranking
	- Then we can create a ROC curve
- [[ROC Curve]] plots the true positive rate against the false positive rate
	- Visualizes performance of a binary classifier
	- Evaluates trade-off vs sensitivity and specificity
- **True Positive Rate (TPR) ([[recall]])** - Fraction of actual positive cases that are correctly classified
	- $TPR = \frac{TP}{TP + FN}$
	- Also called "[[sensitivity]]"
- **False Positive Rate (FPR)** - Fraction of actual negative cases that are classified to the positive class
	- $FPR = \frac{FP}{TN + FP}$
- [[specificity]] - true negative rate (TNR) or the recall of the negative class
	- $TNR = \frac{TN}{TN+FP}$
	- "negative recall"
- Note that $FPR = 1 - \text{specificity}$
- ROC curve measures ranking:
	- highly skewed data -> difficult to do binary classification, so we do ranking instead
	- Compute Pr(+|x) for each test instance / case ([[scoring]])
		- We use a threshold to decide classification according to the needs of the application
			- Above the threshold -> positive
			- Below the threshold -> negative
		- Sometimes we can do any threshold, but directly work on the ranking in an application
	- What if we have 2 classifiers? How do we compare them, just plotting is not enough
		- We can use Area under the curve (AUC) to directly measure the two

- area under the ROC curve (AUC) for overall comparisons (integrals yay)
	- If we need to compare 2 classifiers, check AUC.
	- If AUC for $C_i$ is larger than AUC of $C_j$, then $C_i$ is considered to be better than $C_j$.
	- Perfect classifier -> $AUC = 1$
	- Classifier making random guesses -> $AUC = 0.5$
- How to draw a ROC curve (See example 13)?
	- 1) Sort test cases in decreasing order of classifiers output values
	- 2) partition rank list into 2 subsets/parts for every test case
		- test case in upper part -> positive case
		- test case in lower part -> negative case
	- 3) For each partition, compute TPR and FPR values
	- 4) Connect adjacent points between empty upper part (0,0) and empty lower part (1, 1)
